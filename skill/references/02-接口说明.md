# 接口与配置说明

## 一、入库服务接口

**基址**：`http://127.0.0.1:8090`
**脚本**：`<你的工作目录>\ingest-service.py`
**启动**：`<你的工作目录>\入库服务.ps1`（start / stop / status / restart）

### GET /health

一次性检查五项依赖。

```json
{
  "ok": true,
  "checks": {
    "ollama":     { "ok": true, "models": ["nomic-embed-text:latest"] },
    "dify":       { "ok": true },
    "ffmpeg":     { "ok": true, "path": "D:\\ffmpeg\\bin\\ffmpeg.EXE" },
    "node":       { "ok": true, "path": "...\\node.exe" },
    "douyin_api": { "ok": true }
  }
}
```

**`ok` 是五项的逻辑与** —— 任一项 false，整体就 false。
**失败项会带 `error` 字段**，写的是具体异常。

### POST /ingest

提交链接，**立即返回**（不等待处理）。

```json
// 请求
{ "url": "https://v.douyin.com/xxxxx/" }
// 可选：{ "url": "...", "dataset_id": "<指定别的知识库>" }

// 响应 202
{ "job_id": "7535c3e7f250", "status": "queued",
  "message": "已收到，正在后台处理", "poll": "/jobs/7535c3e7f250" }
```

### GET /jobs/<job_id>

查单个任务。

```json
{
  "job_id": "7535c3e7f250",
  "url": "https://b23.tv/HHucesn",
  "dataset_id": "<你的知识库 ID>",
  "status": "done",          // queued | running | done | failed
  "stage": "已完成",          // 排队中 | 下载中 | 转写中 | 纠错中 | 入库中 | 已完成 | 失败
  "progress": 100,           // 0 | 5 | 25 | 60 | 80 | 100
  "created_at": 1791361342.5,
  "title": "...",            // 下载完成后才有
  "duration": 86.0,
  "words": 453,
  "doc_id": "3ed12cb9-...",
  "doc_name": "bilibili-...",
  "elapsed": 32.0,
  "message": "《...》已入库",
  "error": "...",            // 仅 failed 时有
  "logs": ["[16:22:22] 开始处理 ...", "..."]
}
```

**进度阶段对应关系：**

| progress | stage | 干什么 |
|---|---|---|
| 0 | 排队中 | 已受理，等线程 |
| 5 | 下载中 | 解析链接 + 下载视频 |
| 25 | 转写中 | 抽音频 + faster-whisper 识别 |
| 60 | 纠错中 | 调 Dify 工作流做纠错和知识点提取 |
| 80 | 入库中 | 切块 + 上传 + 建文档 + 等索引 |
| 100 | 已完成 / 失败 | 结束 |

### GET /jobs

最近 20 个任务，按 `created_at` 倒序。

```json
{ "jobs": [ { ...同单个任务结构... } ] }
```

**⭐ 任务落盘在 `_ingest-jobs.json`**，服务重启后历史还在（但丢失正在跑的任务状态）。

## 三、调 Dify 的两种方式

### 方式一：CLI（推荐，会自动刷新 token）

```powershell
$node = "<你的 node 路径>"
$cli  = "<你的 dify-mcp 目录>\bin\difywf.js"
Set-Location "<你的 dify-mcp 目录>"

# 跑工作流（草稿版）
& $node $cli workflow run-draft --app-id <app_id> `
  --inputs ('{"query":"问题"}') --query "问题" --base-url http://localhost

# 发布
& $node $cli workflow publish --app-id <app_id> --confirm --base-url http://localhost
```

### 方式二：裸调 API（要自己处理 token 刷新）

```javascript
import { apiCall } from "./src/core/http.ts";
import { csrfValue } from "./src/core/cookies.ts";
import { refreshConsoleCookies, storeCookies } from "./src/core/auth.ts";

let cookies = /* 从 ~/.difywf/hosts.json 读 */;
const rf = await refreshConsoleCookies(BASE, cookies);
if (rf.ok) { cookies = rf.data; storeCookies(BASE, cookies); }
const csrf = csrfValue(cookies);

await apiCall(BASE, "/console/api/...", { cookies, csrfToken: csrf, body });
```

**⭐ 坑：CLI 会自动刷新 token，裸调 `apiCall` 不会。**
不刷新会遇到 `AUTH_EXPIRED / Token has expired`，而同一时间 CLI 却是正常的。

## 四、常用 API 路径

| 功能 | 路径 |
|---|---|
| 列知识库 | `GET /console/api/datasets` |
| 列文档 | `GET /console/api/datasets/<ds_id>/documents?page=1&limit=50` |
| 列分段 | `GET /console/api/datasets/<ds_id>/documents/<doc_id>/segments` |
| **检索测试** | `POST /console/api/datasets/<ds_id>/hit-testing` |
| 元数据字段 | `GET/POST /console/api/datasets/<ds_id>/metadata` |
| 文档元数据 | `POST /console/api/datasets/<ds_id>/documents/metadata` |

**⭐ 检索测试的路径是 `/hit-testing`，不是 `/retrieve`** ——
`/retrieve` 属于 service_api，要 OpenAPI Key，用 console cookie 会 404。

## 五、元数据绑定（打主题标签）

**新增视频后必做**，否则该文档会被主题过滤掉。

### 一次性绑所有文档

```powershell
$node = "<你的 node 路径>"
cd "<你的 dify-mcp 目录>"
& $node "_bind-topics.mjs"
```

脚本按文件名关键词自动分类：

| 关键词 | 主题 |
|---|---|
| 书籍转技能 / SKILL / Skill | AI应用 |
| ComfyUI / Agent | AI工具 |
| MiniMax / 显存 / H3 | AI视频 |
| 电商 / 详情页 | 电商运营 |

### 绑定接口格式

```json
POST /console/api/datasets/<ds_id>/documents/metadata
{
  "operation_data": [
    {
      "document_id": "<文档 id>",
      "metadata_list": [
        { "id": "<元数据字段 id>", "name": "主题", "value": "AI工具" }
      ]
    }
  ]
}
```

**⭐ `id` 是元数据字段的 id，不是文档 id，别搞混。**

## 六、更新主题判断提示词

**新增视频后必做** —— 提示词里列的是知识库当前的视频标题和关键词，
不更新的话新视频判不出主题。

```powershell
$node = "<你的 node 路径>"
cd "<你的 dify-mcp 目录>"
& $node "_fix-topic-prompt.mjs"
```

脚本做的事：
1. 从知识库读出每个文档的「知识点」条目
2. 生成新的分类描述（含真实视频标题 + 关键词）
3. 写进 `llm_topic` 节点的提示词
4. 同步到 Dify

## 七、路径配置

**⭐ 脚本里有硬编码的绝对路径，换机器必须改。**

配置文件：`<你的工作目录>\config.py`

| 变量 | 当前值 | 说明 |
|---|---|---|
| `FFMPEG` | `D:\ffmpeg\bin\ffmpeg.exe` | ffmpeg 路径 |
| `FFPROBE` | `D:\ffmpeg\bin\ffprobe.exe` | ffprobe 路径 |
| `WORK_DIR` | `<你的视频目录>` | 视频和转写稿存放 |
| `DIFY_MCP_DIR` | `<你的 dify-mcp 目录>` | Dify CLI 位置 |
| `NODE` | `<你的用户目录>\.dsh\...\node.exe` | Node 运行时 |
| `XHS_COOKIE_FILE` | `<你的工作目录>\_xhs-cookie.txt` | 小红书 cookie |

**改完要重启入库服务**（Python 不热重载）：
```powershell
& "<你的工作目录>\入库服务.ps1" restart
```

## 八、合规相关

**知识库只存三类内容，不存他人原文：**

| 分节 | 存不存 | 原因 |
|---|---|---|
| `## 知识点` | ✅ 存 | 提炼产物，属于「思想」，不受著作权保护 |
| `## 问答对` | ✅ 存 | 同上，且问答形式对检索更友好 |
| `## 关键参数（原文摘录）` | ✅ 存 | **数值、参数名是事实，不受保护**；且是检索最有用的信息 |
| `## 校对稿` | ❌ **不存** | 他人完整原文 = 受保护的「表达」 |

**控制开关**：环境变量 `KEEP_SECTIONS`
```powershell
# 默认（合规）
# 不设 = 只留 知识点 + 问答对 + 事实摘录

# 回退（三节全存，仅测试用）
$env:KEEP_SECTIONS = "校对稿,知识点,问答对"
```

**实现在 `one-click-pipeline.py` 的 `build_chunks()` 和 `extract_facts()`。**
事实摘录的封顶是 `FACT_MAX_CHARS = 700`，防止变相保留全文。
